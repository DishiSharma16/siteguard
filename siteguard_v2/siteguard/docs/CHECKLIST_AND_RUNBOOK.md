# Build runbook and requirement checklist

## Roles
- A Pipeline lead: PipeGen five stages, TensorRT, INT8, live camera
- B Alerts lead: zone_dwell.py, Mosquitto, MQTT/JSON, failure-case demo
- C Firmware + evidence lead: FirmGen PRD, flash, UART, traceability, README, submission

## Pre-flight (15 min)
- [ ] `pipegen --version` prints 0.5.1 (X11 session, videos under /home)
- [ ] Signed in to CraftifAI account (both tools)
- [ ] FirmGen v0.4.1 installed, ESP-IDF v5.5 confirmed
- [ ] USB camera works (`ls /dev/video*`)
- [ ] `sudo apt install mosquitto mosquitto-clients` ; `pip install paho-mqtt`
- [ ] Record a 60 s backup video of a person walking into a taped zone (under /home)

## Phase 1: PipeGen (Track A mandatory)
Requirement text to paste (edit to taste):
> Detect and track people in a live USB camera stream. Define a hazard zone and raise an alert when a tracked person stays inside the zone for more than 2 seconds. Overlay the zone and track IDs on the live display, write per-frame JSON metadata, and publish alerts over MQTT. Use the fastest accurate person detector, compile to TensorRT.

- [ ] Stage 1 Requirement saved
- [ ] Stage 2 Pipeline IR node graph -> screenshot to evidence/pipeline_ir_graph.png
- [ ] Stage 3 Model chosen (note name/version)
- [ ] Stage 4 Compiler: TensorRT FP16 engine + speed report -> screenshot
- [ ] Stage 5 Run on video file first, then USB camera
- [ ] Inspect ONE line of PipeGen's JSON output; set keys in alerts/config.json input_adapter
- [ ] Copy export folder + run.sh into pipegen_export/

## Phase 2: Alerts (actionable output)
- [ ] `python3 alerts/zone_dwell.py --simulate` prints 1 ALERT and 1 CLEAR (the pass-through must NOT alert)
- [ ] Tune zone_polygon_norm to the taped zone
- [ ] `mosquitto -c alerts/mosquitto.conf` ; `mosquitto_sub -t siteguard/alerts -v | tee evidence/mqtt_log.txt`
- [ ] Live: `tail -F <pipegen_json> | python3 alerts/zone_dwell.py --stdin --mqtt`
- [ ] Ask a mentor whether PipeGen can publish detections over MQTT itself; if so subscribe instead of tailing
- [ ] evidence/incident_log.jsonl contains real entries

## Phase 3: Edge Optimization bonus
- [ ] Build INT8 engine in the Compiler stage (calibrate on ~100-500 frames of YOUR scene)
- [ ] Export FP16 vs INT8: FPS, latency, power, accuracy -> evidence/fp16_vs_int8.md + screenshots
- [ ] Run the live demo on INT8 and confirm alerts still fire (the practical accuracy test)
- [ ] If a Jetson is available, run there and add power numbers

## Phase 4: Closed Loop + Live Intelligence (ESP32 + LED + buzzer)
Start only when Phases 1-2 work live.
- [ ] FirmGen: upload firmware/ESP32_SiteGuard_PRD.md, review categories, FREEZE requirements
- [ ] Generate, build, flash. Wi-Fi/broker via menuconfig (broker = laptop IP on a phone hotspot or travel router, not venue Wi-Fi)
- [ ] Manual test: `mosquitto_pub -t siteguard/alerts -m '{"state":"ALERT"}'` -> LED + buzzer on
- [ ] UART output -> evidence/uart_output.txt; clip of physical behaviour
- [ ] Traceability report -> evidence/traceability_report.pdf
- [ ] Push project via FirmGen Git view into firmware/
- [ ] Live Intelligence: Enable Telemetry, rebuild, flash, show monitor in demo
- [ ] Measure latency (ts_ms vs receive time, or slow-mo video); put the real number in the description
- [ ] Ask organisers whether a Track A entry can claim Live Intelligence (listed under Track B)
